# IdeaPickup 设备直连千问与思源改造计划

更新日期：2026-11-03。状态：步骤一至七已完成并通过独立审计。交付为本地候选。

本次修订将旧固件中失效实现的清理列为七步内的必做工作；实现直连但未完成清理与相应验证，不算本轮完成。后续残留项的处理见[直连固件清理补充](FIRMWARE_CLEANUP.md)。

目标是让用户完成设备联网、填写千问与思源凭据后，即可录音、转写并投递思源，无需部署 IdeaPickup 中继服务。有卡和无卡均覆盖正常联网流程；有卡保留本地录音、处理状态及手动提交能力。**无卡断网、断电后的恢复能力不纳入本轮完成条件**，留待后续单独评估。

本计划以提交 `cf05bb53aa6c89fcd813597cf7d89ff78cbe4b88` 为分析基线，适用于现有 `vocat16` 和 `spotpear`。开始实施时必须重新核对当前分支、提交和修改，不覆盖随后产生的工作。R12 已完成，本计划不重开其低电跳过项或斑梨历史看门狗延期项，也不把这些限制改记为通过。

## 一 本轮范围和实施原则

### 必须实现的行为

- 设备直接请求千问云端，取得转写文本后直接投递思源云端收集箱；模型仍在云端运行。
- 有卡录音先可靠保存音频，再自动触发一次处理。网络不可用时保留同一处理意图，恢复联网后继续；不因开机、浏览列表或打开详情自动提交其他本地录音。
- 上述自动处理只适用于已启用联网转写的录音；仅本地使用时只保存音频，之后启用转写也不自动补交这批录音。切换回仅本地使用时停止发起新的云请求，保留原音频及已知状态。
- 有卡未处理、已取消或允许重试的失败记录可以手动提交；处理中可以请求取消；已送达记录只显示结果，不提供再次提交入口。
- 有卡详情读取本地处理状态，不扫描完整音频、不计算完整音频 SHA、不因查看详情调用云端。
- 无卡使用实时识别流程，录音期间发送音频，停止后收齐已确认结果再投递。正常完成的记录显示结果，不提供设备端重新提交音频的入口。
- 录音、播放、语音启停、USB 麦克风、存储模式锁定、按需探卡和现有页面设计继续适用；只改本次直连需要的接口、状态、字段与提示。
- 原录音、历史状态、编号、Wi-Fi 和恢复材料保留。已有历史不得因新版本误变成待处理任务。

### 不纳入本轮的工作

| 项目 | 本轮处理方式 |
|---|---|
| 无卡断网后的续流、补传及缺失音频重建 | 后续方向；本轮只保证有界等待、清楚的失败反馈和资源释放 |
| 无卡断电后的音频、文本及云任务恢复 | 后续方向；不承诺关机后继续完成未结束的无卡录音 |
| 自建服务和直连之间的通用双引擎、自动切换 | 不新增；本轮主线是设备直连 |
| LLM 聊天、TTS 对话、MCP、其他转写供应商 | 不新增 |
| 停用生产中继、删除后端源码或撤销原凭据 | 不由本轮自动执行；现有部署和旧固件保留为回退参考 |
| 全仓库重构、通用任务框架、完整音频指纹机制 | 不新增；复用现有任务与存储入口 |

### 防止复杂度重新增长

1. 优先使用锁定 SDK 的 HTTPS、WebSocket、证书校验和现有录音组件；只引入实际需要的依赖，不整体搬入官方智能体或小智聊天应用。
2. 使用有限缓冲、明确状态及少量持久化字段，不按每一帧建立记录，不把所有历史详情常驻 RAM。
3. 状态没有变化时不写 SD／Flash；无工作时网络任务休眠；终态停止查询和重连。保留现有配置页隐藏后停止状态轮询的行为。
4. 直连接口若不要求音频摘要，不为了仿照旧中继额外在设备上计算 SHA。现有 SHA 字段仅保留兼容读取，不作为详情显示的先决条件。
5. 网络状态不确定必须如实显示。不能把“请求已经发送”当作“转写成功”或“思源已收件”，也不能为消除不确定状态自动重复投递。

### 旧固件清理范围与保留边界

清理随直连替换推进，不留到交付后另做，也不增加第八步。步骤一逐项登记“复用／替换／删除／兼容保留”，步骤二至五完成对应清理，步骤六验证，步骤七独立审计收口。下表定义范围，完成勾选仍只维护在各步骤的“完成标准”。

| 范围 | 核对后必须清理的内容 | 必须保留的边界 |
|---|---|---|
| 中继专用通信 | 被直连替代的配对鉴权、设备 token 请求、上传会话／分块 ACK、任务查询及取消协议 | HTTPS／TLS、WebSocket、超时、取消和通用网络执行者按实际需要复用；不按文件名整模块删除 |
| 后台运行资源 | 旧协议独占的任务、队列、定时器、重连、状态轮询及重复缓存，连同其初始化／销毁入口 | 当前录放、USB、配网、按需探卡和直连任务需要的调度保留；不为“兼容”继续后台访问旧服务 |
| 任务与存储 | 失效的上传偏移／ACK／中继恢复路径、重复状态写入及不再使用的音频 SHA 路径 | 原音频、编号和历史结果保留；有卡直连恢复与无卡失败收尾继续实现；旧格式只保留必要读取／转换 |
| 配置与界面 | 失效的中继地址／配对码入口、请求字段、事件处理、提示、缓存和运行时配置读取／写入 | Wi-Fi、仅本地模式及新供应商配置保留；旧配置按回退方案保全，不全量清空 NVS／SD，也不误用旧 token |
| 构建与依赖 | 无调用模块、旧协议专属组件、编译开关、构建注册、过时示例及测试入口 | 共享依赖经调用关系核实后再处理；不删除 TLS、签名验证或其他现有功能需要的加密组件 |
| 测试与文档 | 固件已不存在的旧接口测试接线、失效操作说明和产物清单引用 | 仍适用的行为断言移到新路径继续验证；保留后端独立测试及有用途的历史资料，并注明适用版本 |

不得只隐藏页面或用永久关闭的开关包住整套废弃实现就宣称清理完成。删除已无用途的产品源码和构建引用；历史实现由 Git 历史及已有恢复材料保留，不在固件内再维护一套备用中继引擎。确需保留的格式字段或解析器应注明用途、调用位置和保留理由，不要求为了清理而重写所有旧数据。

本清理不包含停用现有服务器、删除后端源码、撤销凭据、清除用户数据或删除私有档案。新协议可能增加必要资源，不能承诺总固件体积或 RAM 必然下降；验收要证明失效实现已移除、资源变化可解释且满足既定上限。

## 步骤一 确定接口与改造边界

本步交付：[接口、状态、资源、升级及清理决定](DEVICE_DIRECT_CLOUD_STEP1.md)；[三轮独立审计报告](DEVICE_DIRECT_CLOUD_STEP1_AUDIT.md)最终PASS。工作勾选表示本步分析已交付；下方完成标准只在独立审计通过后勾选。

### 详细工作

- [x] 核对现有有卡 WAV、无卡音频编码、采样率、任务状态、元数据容量及线程／内存分配，记录可直接复用部分。当前后端约 180 秒分段是参考，不直接当成新固件的最终限制。
- [x] 核对千问文件转写和实时识别的实际协议、模型、地域、鉴权、音频格式、单请求限制、最终结果事件、错误和取消能力。模型选择服务于转写，不引入聊天生成或 TTS。
- [x] 核对思源收集箱的请求格式、成功响应、限制和是否提供可用的幂等／结果查询能力。文档未承诺的能力不得自行假定存在。
- [x] 冻结直连任务状态及转换：本地保存、等待联网、转写中、待投递、投递中、已送达、失败、取消中、已取消、投递结果不确定。能由现有状态表达的优先复用，不为每个内部动作扩展公共状态。
- [x] 区分“同一条录音”“同一次用户提交”“一次供应商请求”。文件请求中断后，只有供应商明确支持的续传／查询才能复用；不能把旧中继的分块 ACK 协议直接套在千问接口上。
- [x] 确定有卡分段边界、文本缓存位置、分段完成检查点、失败重试次数及退避；网络恢复可能需要重发未确认的一段，不宣称字节级断点续传或零重复计费。
- [x] 填定资源与超时表：音频发送缓冲、响应缓冲、文本上限、任务栈、同时连接数、无卡短暂等待时长、单请求等待窗口、连续失败重试上限、历史容量和淘汰规则。记录依据及容量用尽时的行为，不把这些内部常量都做成用户配置项。
- [x] 决定配置与历史兼容方式。新固件首次启动不自动把旧中继待办转换为直连任务；已由旧中继接收的任务保留原来源和“旧服务待核对”含义，不能自动重新转写。新增格式若不兼容，采用最小版本转换并提供匹配的回退数据。
- [x] 确定长期凭据的输入渠道和本地保存方式。当前开放热点上的明文 HTTP 不能未经处理就用于输入长期供应商凭据；比较已有安全配置能力并选最小适用方式，不自行重做加密协议。涉及用户操作方式变化时，先明确方案。
- [x] 记录官方参考代码的版本、许可证、SDK 兼容性和裁剪范围。小智的自有会话协议与千问协议不同，只复用适用的音频与连接处理方法。
- [x] 明确处理期间更换凭据、切换账号或切回仅本地模式的边界；不会把原任务的正文静默发到新的思源账号，也不建立无限增长的历史服务配置目录。
- [x] 建立覆盖上述清理范围的处置清单，逐项记录文件／符号／配置或依赖、现有调用者、处置类别、理由、所在实施步骤和验证入口。核实共享用途后才列为删除；兼容保留项说明数据用途和读取／转换边界。该清单记录处置证据，不另设一套重复完成勾选。

### 完成标准

- [x] 文件转写、实时转写和思源投递三个接口的输入、输出、错误及限制均有准确来源和适配决定。
- [x] 状态转换覆盖断线、取消、重复点击、失败、终态及结果不确定；旧任务不会自动触发新的付费处理。
- [x] 仅本地模式、重新启用转写及凭据变更的任务行为已确定，不产生批量补交或错误目的地投递。
- [x] 资源、容量和超时表全部填定；后续能据此检验，不留下“无限等待／缓存／重试”。
- [x] 凭据输入、存储和升级回退方案确定，未引入未经需要的框架或秘密暴露路径。
- [x] 无卡恢复排除范围明确，现有已确认产品规则没有被隐式删除。
- [x] 复用／替换／删除／兼容保留清单覆盖旧通信、运行资源、存储、配置、构建和测试文档；每项有调用依据、负责步骤及验证方式，无未说明用途的保留项。

### 验证和交付

以协议样例、现有代码和边界场景走查验证；本步骤不需要调用真实转写或写思源。交付接口与状态决策记录、资源表、必要改动文件及清理处置清单，以及尚需用户决定的具体差异；这些决策未确定前不进入依赖它们的实现。

## 步骤二 实现设备直连基础能力

本步交付：[协议实现、验证与清理去向](DEVICE_DIRECT_CLOUD_STEP2.md)。[五轮独立审计](DEVICE_DIRECT_CLOUD_STEP2_AUDIT.md)最终PASS；工作与完成标准均已通过。

### 详细工作

- [x] 复用现有 HTTP／TLS 和网络执行入口，提供文件转写、实时识别、思源投递所需的最小调用能力。避免同时长期保留多个 TLS 会话。
- [x] 文件转写支持按块读取和发送。采用 Base64 时边读边编码，正确计算请求长度和编码边界；不先拼接整个 Base64 JSON。若采用压缩格式，必须核对供应商支持的封装，而不是把现有裸 Opus 帧直接当成文件。
- [x] 实时识别实现鉴权、会话建立、音频发送、最终文本确认、停止和释放；明确临时识别结果与最终结果，避免文本重复拼接。
- [x] 按供应商接口处理响应分块、UTF-8 跨块、正文大小限制、超时、限流、凭据错误和服务异常。仅对可安全重试的阶段执行有界重试。
- [x] 思源投递复用现有标题／正文规则，正确转义文本。只有合法成功响应才记已送达；已发出请求但失去响应时记结果不确定。
- [x] 取消和超时由请求所有者收尾，关闭会话并释放内存；不在公共事件回调中执行长时间阻塞操作，不遗留后台重连。
- [x] 使用本地合成 HTTP／WebSocket 服务覆盖正常与异常行为；生产固件不接入测试旁路、不关闭证书校验、不包含真实测试凭据。
- [x] 随调用方迁移删除旧中继协议客户端、独占任务／队列／定时器及其构建注册；共享 HTTP／TLS 能力复用。仍由步骤三、四调用的旧接口登记到对应清理项，不提前破坏构建，也不在最终候选中留下无调用代码或备用中继开关。

### 完成标准

- [x] 三类调用均能与合成服务完成协议往返，发送内容、终态和错误分类符合步骤一的决定。
- [x] 大输入流式处理，分配不随整条录音长度增长；响应超限时明确失败而非截断后报成功。
- [x] 凭据错误、限流、超时、坏证书、非法响应和取消均能退出到明确状态。
- [x] 连接、任务和缓冲区在成功、失败及取消后均正确回收；无持续增长的资源占用。
- [x] 请求写出与实际送达分开记录；不会因超时自动重复投递思源。
- [x] 已迁移路径的旧协议代码与专属后台资源已清理；仅因后续调用方尚未迁移而暂留的项已明确归入步骤三、四的清理范围，无未登记残留。

### 验证和交付

新增或扩展实际生产调用路径的测试，记录每个故障发生在请求前、请求中还是响应后。执行相关既有网络回归及两板编译，交付接口代码、可重复测试入口和结果，不把合成通过写成真实云端通过。

- [x] 在卡上保存已确认分段、必要的转写文本和投递进度。文本只为完成或恢复任务服务，不新增设备全文阅读功能；成功或取消后按既定规则清理临时文本，保留最终状态和原音频。
- [x] 失败恢复只继续当前任务的未完成阶段。已有文本的任务投递失败时，不重新转写音频；已送达的任务不再次提交。
- [x] 将详情按钮接入真实状态：未处理／已取消／可重试失败显示提交；处理中显示取消；已送达只显示结果。投递结果不确定使用明确提示，不把普通重试按钮当作安全重发。
- [x] 用户取消后停止尚未发出的请求和排队动作。已经发到供应商的请求可能产生费用，已发到思源的内容也不能保证撤回；这些情况保留真实结果，不显示虚假的已撤销。
- [x] 保持录音与存储操作的互斥及录音模式锁定。卡写入失败、拔卡或容量不足时保护原音频，按现有错误行为结束，不借本次扩展此前延期的强提醒设计。
- [x] 兼容已有成功、失败、排队和旧服务未决状态；不重写所有历史，不扫描音频计算 SHA，不恢复开机自动提交旧录音。
- [x] 删除被直连替代的有卡中继会话、分块 ACK、远端查询与重复状态缓存／写入路径。旧记录的字段只在必要的解析／转换处保留，不再驱动旧任务调度；旧服务未决记录保留来源和待核对提示，不以重新提交代替核对。

### 完成标准

- [x] 新录音自动一次、离线待处理、手动提交、取消及终态按钮符合约定，重复点击不创建并行任务。
- [x] 跨越至少两个转写分段的录音能顺序合并，无明显丢段、重段；处理内存不随总时长增长。
- [x] 断线及重启后的有卡任务从可靠检查点继续；已确认文本不重复转写，投递不确定不自动重发。
- [x] 已有音频、编号和历史结果保留；旧服务任务不会被直接映射为新的直连提交。
- [x] 详情读取只访问轻量本地状态，未恢复完整音频 SHA、HTTP 查询或无变化写入。
- [x] 取消、失败和完成均有临时文件清理规则，不能留下无限增长的中间文件。
- [x] 有卡旧中继调度和冗余缓存／写入已移除；兼容读取可显示旧状态且不发起旧服务请求、不重排队，也不破坏原音频及回退资料。

### 验证和交付

扩展 SD 同步、元数据及详情回归。使用固定音频和文本替身核对分段覆盖；在转写前、分段确认后、投递前及响应丢失处注入故障。物理恢复测试与步骤六的集中组安排，避免在本步骤反复要求用户换卡。

### 最少人工操作的分组

| 批次 | 用户配合 | 随后自主执行 | 合并覆盖 |
|---|---|---|---|
| A 喵伴有卡 | 一次完成必要凭据配置；录一条短真人语音并确认收件；检查提交／取消按钮与布局 | 用合成服务连续跑分段、长录音、失败和重连；核对已有数据与内存 | 完整共享逻辑、配网页、实际千问及思源链路 |
| B 喵伴无卡 | 安全停止卡访问后取卡一次；完成一条短真人录音并确认结果 | 在无卡状态连续跑长流、背压、失败退出和清理；合并必要重启检查 | 无卡正常链路与本轮失败边界；结束后仅插回一次 |

## 三 后续方向 无卡断网和断电恢复

此项不属于上述七步的阻塞条件，也不在本轮做恢复能力验收。后续应先回答以下问题，再决定是否实施：

1. 千问是否允许查询或恢复同一实时会话，能取回哪些已确认结果；如果不支持，缺失音频是否还有任何来源。
2. 是否只保存最终文本／少量状态就足够，还是必须持久化音频；各自对 Flash 容量、磨损、耗电和复杂度有什么影响。
3. 断网和断电分别能恢复到什么时间点；不能恢复时，用户最需要的是已确认的部分结果、明确失败，还是强制要求使用 SD 卡。
4. 发送思源后响应丢失如何确认结果，是否有官方幂等能力，不能实现时如何避免重复笔记。
5. 是否确实值得扩展恢复能力，还是把有卡模式作为需要长录音和可靠恢复时的推荐方式。

本轮对这些问题只保留决策入口，不预设必须新增 Flash 音频缓存、对象存储或重新引入中继。
