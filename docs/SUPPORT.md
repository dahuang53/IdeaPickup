<a id="daily-use"></a>
## 日常操作

| 要做什么 | 操作与结果 |
|---|---|
| 打开操作页 | 点猫脸；约 60 秒无操作后返回猫脸，有效控件操作会重新计时 |
| 录音 | 点“开始录音”，看计时／电平；完成后点“停止录音”，等待保存或上传结果 |
| 语音启停 | 说“你好喵伴”，等唤醒反馈后说“开始录音”或“停止录音”；识别不稳定时可用触摸 |
| 找已有录音 | 打开列表，右侧翻到更早的录音，左侧回到更新的；点一条进入详情 |
| 有卡回放 | 在详情中播放，支持暂停、继续、停止；录音与回放互斥 |
| 查看无卡记录 | 查看编号、时长和处理状态；没有播放入口 |
| 更换 Wi-Fi／服务 | 长按猫脸约 3 秒，手机连接屏幕热点，手动打开 `http://192.168.4.1` |
| 暂停联网同步 | 在配网页选择“仅本地使用”，再点启用并确认实际状态；已有配置会保留 |
| 使用 USB 麦克风 | 仅 16 MB 喵伴：连接电脑数据 USB，说“你好喵伴”后“打开麦克风”，在电脑应用选择设备的 USB 音频输入；屏幕可静音、取消静音、退出 |

USB 麦克风与设备录放不能同时使用；退出后恢复普通设备操作。没有电脑主机、只接充电器时不能用作电脑麦克风；首次连接的默认静音状态以设备屏幕为准。斑梨没有本项目的 USB 麦克风功能。

### 有卡与无卡怎样切换

每条录音**开始时**检查卡是否可用，确定本次模式：有卡则写卡；无卡则需要已配对且可用的联网服务。无卡录音中插卡不会改变本条去向，后续录音才重新判断。有卡录音中卡脱落或写入失败，会停止／报告存储错误，不自动转成无卡录音；更醒目的强提醒仍未实现。

纯猫脸待机不持续探卡，可能保持最后确认的模式。进入显示存储状态的操作页／SD 列表后才检查，持续可见时约每 5 秒检查；录音开始前再次确认。因此在猫脸页插拔卡后没有立即变化并不一定是故障。探卡策略减少无需求的周期唤醒，但没有实测续航增益承诺。

猫脸的快／慢眨眼分别对应已确认的无卡／有卡模式；录音中以本条模式为准。约两分钟静置进入表情待机，可用唤醒词唤醒。取卡前停止录放、保存和同步，最好在关机后操作；不要在写入中拔卡，不自动格式化或删除旧文件。

<a id="data-and-status"></a>
## 音频、文字与任务状态

| 模式／位置 | 保存什么 | 可以怎样使用 |
|---|---|---|
| 有卡设备 | SD 上的录音与记录信息 | 离线录放；启用转写服务后同步待处理录音 |
| 无卡设备 | 本地任务元数据、有限的在途缓存 | 联网分块上传、查看结果；没有持久音频库／回放 |
| 自管中继 | 仅为处理和失败重试保留有期限的音频／正文 | 不提供音频下载或回放接口 |
| 思源云端收集箱 | 成功投递的文字 | 在思源收集箱接收，再自行整理到笔记本 |

中继在成功或拒绝后清理暂存音频，失败／中断的闲置暂存最长 24 小时，查询状态不续期；投递完成清理暂存正文。无卡模式不承诺保存尚未被服务器确认的音频尾部，不能用它代替有卡离线录音。

启用“转写服务”可能自动处理卡内尚未同步的旧录音；在准备好地址、账号和上传范围前保持“仅本地使用”。电脑部署仍会将待转写音频送到千问，并把文字送到思源云端，不是离线识别。

| 看到的状态／错误 | 含义与处理 |
|---|---|
| 已连接／已保存／已配对 | 分别是 Wi-Fi 连通、配置持久保存、服务配对；三者不能互相替代 |
| 等待上传／处理中 | 任务未结束，保持网络，稍后刷新；不要重复新建任务 |
| 已同步思源／已送达 | 中继已获得投递确认，到同一账号的云端收集箱查看 |
| `qwen_rejected`／转写失败 | 看后台任务原因，检查千问额度、权限、音频和配置；在界面允许时重试该条 |
| `siyuan_uncertain`／投递结果不确定 | 先查收件箱是否已有该条，再在后台对这一条核对确认；不要盲目重发，以免重复 |
| 暂存到期／已清理 | 无卡音频已不在中继，不能靠刷新恢复；保留状态不表示仍有音频 |
| 凭据失效／未配对 | 检查设备是否在后台被撤销、服务地址是否正确；确认后用新配对码重新配对 |

重试使用当前配置，可能新增供应商调用费用；只在故障原因已处理且界面提供重试时执行。单条投递不确定不要通过清库、全局重置或重录全部音频解决。

<a id="troubleshooting"></a>
## 按症状排查

### 镜像下载失败／提示 403 或找不到版本

先确认复制的是[当前版本的完整镜像引用](PUBLIC_RELEASE.md#配套-docker-镜像)，包括标签和摘要。发布镜像可匿名获取，不需要另建拥有写入权限的 GitHub 令牌。网络、代理或 GHCR 临时错误可能让拉取失败；先确认能访问 GHCR，再重试一次，仍失败则保留脱敏错误报告，不修改全局认证或改用来历不明的镜像。也可按[部署说明中的自行构建入口](DEPLOYMENT.md#deploy-diagnostics)，从相同发布源码构建本地镜像。

<a id="admin-unreachable"></a>
### 后台打不开／第一次不知道地址

1. 地址来自部署配置，不是设备热点。按[地址表](DEPLOYMENT.md#addresses)在服务地址后追加 `/admin/`，保留端口和路径。
2. 在部署机器运行[状态与日志命令](DEPLOYMENT.md#deploy-diagnostics)。先解决 Docker 未运行、镜像未拉取、容器退出或端口占用，不先重建数据卷。
3. 本地部署确认电脑 IP 未变、电脑没有休眠。手机与电脑需可互相访问，访客 Wi-Fi／AP 隔离或防火墙可能阻断 8765；设备只能连接 2.4 GHz Wi-Fi，电脑可接同一路由器的有线网络。
4. HTTPS 部署确认域名解析、证书链和 Nginx 路径；`/memo/admin/` 返回 404 时检查是否错误地截掉了 `/memo` 前缀。不关闭证书校验。

### 手机已连热点，但 192.168.4.1 打不开

确认设备仍在配网界面、手机连接的是屏幕所示热点，在地址栏完整输入 **`http://192.168.4.1`**，不要用 HTTPS 或搜索框。热点不提供互联网；手机提示时选择保持连接。当前版本不会自动弹系统配网页，需使用普通浏览器。

若仍失败，看手机热点详情是否取得 `192.168.4.x` 的 IPv4 地址；`169.254.*` 或没有地址表示尚未取得可用地址，和网页本身的问题不同。先保留错误提示，再退出／重新进入配网，重新选择保存的热点，不要求每次忘记网络。关闭热点后该页面不可访问是正常的。切换 App 后返回应仍可访问，重新加载可查询已提交操作的结果。

### Wi-Fi 连接失败／找不到网络

设备只支持 2.4 GHz。确认所选网络、密码和覆盖范围；隐藏网络可用“手动输入其他网络名称…”。失败的连接尝试不会把成功保存的原网络覆盖成错误值。等待网页实际状态，不把“已提交”当“已连上”；修改服务地址不需要重填家庭 Wi-Fi。

### 服务一直未配对／提示检查地址和配对码

- 确认使用 R12 配套后端，旧改造前服务即使健康检查通过，也可能不支持当前配对接口。
- 设备填写服务根地址，不带 `/admin/`；自定义端口和子路径必须保留。后台从手机正常打开只能证明手机可达，设备也必须已连接家庭 Wi-Fi。
- 配对码来自后台“设备”页，一次性、15 分钟有效，不是初始化码或 API Key。地址未变的已有配对可留空码；更换服务用新码。
- 局域网 HTTP 只接受私有 IPv4；公网域名需可信 HTTPS。不可信证书会被拒绝，设备可能提示“请检查内网/HTTPS服务地址和配对码”。确认设备能正常联网校时、服务器证书域名／完整链匹配，不绕过校验。
- 设置报“录放或任务正在处理”时，停止实际录放／等待任务收尾再保存；若设备空闲仍持续报忙，记录版本与现象并报告，不反复提交。

### 已配对，但没有转写文字

先在后台“配置”检查两个凭据已保存，再看“任务”中对应记录。已配对仅表示设备有访问凭据；TLS 连接检查也不证明供应商认证与调用额度有效。

确认思源使用相同链滴账号、有云端收集箱权限，打开的是**云端收集箱**而非某个笔记本。思源本地内核 Token 不适用于本项目。千问检查地域、模型权限和余额／额度；凭据获取见[后台配置](DEPLOYMENT.md#provider-setup)。遇到投递不确定先查收件箱，不连续点重试。

### 卡未识别／不能回放／录音停止

纯猫脸不轮询卡，请先打开操作页观察；下一次录音也会重新确认。若出现存储错误，先停止录放，关机后核对卡和卡内文件；在电脑备份前不要格式化。项目使用 FAT 文件系统，exFAT 不能当作已支持；不承诺任意卡容量／型号兼容。

无卡记录没有播放按钮是设计行为；有卡记录播放失败则确认原卡仍在、对应音频文件未改名／删除／替换。卡写入失败会停止录音，界面强提醒尚未完成；重要录音期间注意计时与存储状态，已知限制见下文。

<a id="install-troubleshooting"></a>
### 安装失败／没有串口／写完后没有启动

先按[下载模式说明](DEVICE_INSTALL.md#download-mode)区分应用端口和 ROM 端口，核对数据线、端口占用、板型和 16 MB 容量。软件进入 ROM 要求当前固件确实支持对应路径；不支持时只能使用已核实可按到的物理入口。

查看本次 `private/install-runs/` 下的 `result.json`。保护检查、包校验或布局不一致时先停下，不切换板型尝试，不用 `--force`、全片擦除或 `first-install` 强行绕过普通更新的拒绝。写回成功不等于启动成功；保留原备份和错误摘要，报告实际屏幕／端口表现。

### 电脑找不到 USB 麦克风／听不到声音

确认是 16 MB 喵伴、使用数据线且电脑已选择设备音频输入；检查设备是否进入 USB 麦克风模式、是否静音，以及应用是否允许使用麦克风。充电器不是 USB 主机，斑梨不提供此功能。若无法语音开启，可记录识别失败现象；当前不承诺固定识别率，主机挂起／恢复也尚未完整验收。

<a id="known-limits"></a>
## 已知限制：使用前请了解

- **预发布范围**：当前仅两款明确支持的 16 MB 板型；32 MB 喵伴、新板型、原生 Windows／WSL2 刷机与 rootless Docker 未列为通过。
- **低电量**：两板完整真实低电策略／恢复矩阵由所有者跳过，仍未验证。喵伴耗尽后恢复供电保全文件的单次结果，不证明低电阈值、过程或全部恢复策略。没有续航时长／省电百分比保证。
- **斑梨看门狗告警**：曾在“热点开启＋USB 导出录音”时发生，根因和影响范围未知。后续未复现不代表消除，不能限定为只影响 USB 导出；也未证实造成录音丢失。已明确延期，仍未解决。
- **存储失败提醒**：当前会停止／报告写入错误；更醒目的强提醒延期，不能视为已交付。
- **USB 与语音**：斑梨没有 USB 麦克风；喵伴本地语音识别仍有波动。真实主机挂起／恢复、可选 30—60 分钟录音及长期主机压力没有标为通过。
- **联网与数据**：无卡依赖网络和中继，未确认音频尾部不保证断电保留；暂存有期限，无云端音频库／回放。后端本地部署仍使用千问、思源云端；不提供离线识别或本地思源内核对接。

## 报告问题
