# 设备直连第四步：无卡实时任务

基线第三步 `0221528`，对应[主计划第四步](DEVICE_DIRECT_CLOUD_PLAN.md#步骤四-接入无卡录音流程)及[第一步冻结决定](DEVICE_DIRECT_CLOUD_STEP1.md)。本步只迁移无卡执行及其必要反馈／清理；第五步再提供供应商配置生产入口。没有刷机、录音或读取真实凭据，没有访问服务器或供应商。

## 执行与边界

`memo_cardless.cpp` 复用原16kHz单声道PCM采集入口和 `network_sync` 单网络所有者；删除无卡专用Opus编码任务、32KiB栈、1MiB ACK环、32KiB网络块、前缀恢复和历史查询。PCM队列65,536字节、发送块最多3200字节；生产者非阻塞且整块入队，满即停止并明确失败，不丢旧数据后报成功。每次入队唤醒已有工作者，没有新轮询线程。

开始前要求联网、模式启用、两项新配置齐全、索引和NVS可用；有界准备等待收到session.updated才允许音频所有者启动麦克风及发布录音状态，握手失败不采集。未持久保留编号、记录和活动事实前不启动云端。Realtime单会话不重连，最终确认文本只保存在256KiB PSRAM中，排序队列／事件／JSON解析沿用第二步上限。临时识别不投递。最终文本按第三步流式整理规则在原缓冲内压缩，完整成功后才投递一次正文；保留编号／导入时间格式，连前缀超过正文上限明确失败，不截断。

停止时在PCM互斥内先确定停止时间、再发布停止，排空不能读到旧时间；队列满或采集失败保留短原因。停止后最多5秒排空队列；传给协议的音频调用期限取剩余排空时间与2秒较小值。最终结果等待含排空最多30秒；思源单次最多30秒，停止后的总收尾最多120秒。零HTTP字节失败／明确429共用最多三次尝试，10／60秒退避及有效Retry-After，等待或请求无法放入总预算即失败。SD与无卡共用一个设备投递间隔，不因切换模式绕开10秒。

取消由连接所有者关闭；取消与完整思源成功竞争时保留成功，可能已发送而无有效结果保持不确定。配置变更／网络断开／背压／超限／异常响应／失败均结束本次流，不重建缺失音频。录音中插卡仍由现有活动门闩及开始时模式锁定，本条不会转为有卡。

## 最小持久状态与历史

原 `memo_meta/records1` 只读；新 `direct1` 单条128字节，显式小端、R1CN版本、校验、状态、配置代次、投递额度、可能投递及短原因，不写音频／正文。独立12字节活动事实；先写记录、commit并由新handle逐字回读，后更新活动键。同值不写；故障锁住新云请求，保留持久事实供下次启动收尾，不删除用户历史挪空间。

创建前要求分区空闲条目至少158且总索引少于1024；固定1024×16字节PSRAM索引、四详情槽，活动／选中槽受保护，按需读NVS，不按历史条数保存全文。混合旧228字节与新128字节记录不承诺必存满1024，以实际条目准入为准。

启动仅整理新direct记录：DELIVERING或可能已投递的CANCELLING转不确定；其他取消完成取消，其余未终态转录音中断。检查孤立记录覆盖记录／活动键之间断电；终态成功落盘后清活动事实，不恢复流或发网络请求。旧活动键原样保留，旧未决记录显示“旧服务待核对”，无重试；旧送达状态继续保留。结束的无卡详情只有本地状态，没有播放／刷新云任务／重新上传入口。

生命周期结束由网络所有者关闭WS／HTTP，归还租约、释放队列及文本、清零配置。仅保留固定历史索引／详情和必要互斥，没有后台保活或历史逐条轮询。

## 适用清理及验证

`test_cardless_runtime.py` 编译实际无卡生产源码、协议核心及编解码，RTOS／NVS／平台IO为明确替身，ASan／UBSan启用；覆盖正常最终文本／投递、无网、凭据、队列满、阻塞、断开、文本／等待上限、取消竞争、有限重试、元数据失败、启动孤立收尾、1023旧＋1新索引边界（显式扩大的逻辑存储只测索引）、6/10条目计数的8064条目混合容量夹具、索引满及循环回收。34项合成用例另覆盖慢握手、准备失败不采集及停止发布交错。协议内部追加同一会话多条最终文本时发现条目槽未清零，已修正并由文本压力回归覆盖。
