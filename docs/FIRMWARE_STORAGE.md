# 固件持久数据入口

当前配置格式以[设备配置契约](contracts/firmware-config-v1.json)及其 codec/适配器路由为唯一定义。本版本只保存一个当前服务及其未完成配对；不导入旧项目数据。

配置与 Wi-Fi 使用独立 namespace。服务保存先提交并完整读回，未知结果自动重新读实际持久数据；坏数据和未知版本不擦除、不当作空的新安装。Wi-Fi 保持原键格式，只补当前保存的错误传播、读回及录放短互斥；多键写入中断可能留下部分 Wi-Fi 变更，返回未确认/下次重新读取，不声称整表原子或掉电零丢失。

编号/任务的唯一入口是[录音任务契约](contracts/firmware-tasks-v1.json)：`memo_ids1` 的单个设备高水位、SD 每条录音的当前任务 sidecar、`memo_meta/records1` 的无卡记录/最后 active marker。旧 cursor/manual 提示、旧 cache 和 native struct 不作为当前身份事实，也不导入历史。每种字节布局只由契约链接的 codec 定义。

SD 编号 I/O 故障时允许独占文件名保住本地录音，不假称已取得全设备编号或自动上传资格；普通重试读实际持久值。任务绑定和真实服务器身份/完整音频 hash/长度核对后才复用状态。配置变化不建立历史服务目录，当前服务/任务边界按上述两份契约引用；没有原卡归属或历史清点步骤。

源码更新在当前 schema 内保持字节布局及 namespace；未来不兼容格式需要单独设计最小兼容转换，不恢复旧业务历史流程。真实 NVS、断电、介质与录放组合状态见[支持表](SUPPORT.md)；主机 shim 和普通构建不能替代这些结果。

无卡状态仍使用 `memo_meta/records1` 中的 228 字节记录，不另增结果 namespace。PSRAM 仅保留最多 1024 条、每条 16 字节的列表索引，详情固定 4 槽；活动录音和选中记录固定在槽内，其他槽按需覆盖。Flash 读写失败不淘汰唯一未上传音频、不删除历史。LVGL 只读缓存快照，本地详情加载由独立于 HTTP 的工作任务执行。没有按历史数量持续增加的详情分配，也没有自动擦除历史的容量恢复流程。

记录 blob 已落盘但 active marker 未提交的中断启动，会将没有允许上传音频的孤立排队记录记为失败；有远端音频可能性时仍保留恢复边界。尚未完成及待核对状态后台只做 GET；已完成的成功／失败历史不因详情打开而联网。无卡设备的恢复动作仅继续当前未完成流，已结束记录的处理重试留在后台。

有卡同步与无卡传输复用一个网络工作任务；有活动无卡流时暂停 SD 同步。仅查询历史状态不创建音频传输线程，也不分配音频块。实际无卡录音需要的固定 32 KB 传输块按需分配并复用，不随历史条数增加；本地详情使用独立的 10 KiB 内部栈，网络请求不会挡住详情切换。两者采用固定内部静态栈。构建使用 SDK 的 64 KiB 内部专用分配保留池，普通 malloc 不能占用此池；为任务栈和 DMA 保留空间，任务栈不放进 PSRAM。普通分配优先使用 PSRAM（SDK 阈值为 0），显式 INTERNAL／DMA 分配仍留在内部；分配器会在首选区域不足时尝试另一种可用区域，不能将此设置当作连续内存保证。

有卡音频身份最多缓存 4 条，仅放在 RAM：首次读取仍完整计算 SHA-256，随后在同一挂载期间复用。命中前核对原 SD 会话仍处于 READY/TRANSFER 状态及文件长度、时间属性；挂载／重新挂载、生成新录音、读失败或卡状态异常都会清空缓存。设备不会覆盖已完成的 WAV；外部编辑须取卡，插回后重新建立挂载和身份。缓存不从同步结果文件装入，不替代首次内容校验，也不允许跨挂载只凭同编号、长度或 FAT 时间戳复用结果。

HTTP 使用锁定 ESP-IDF 的 TCP/TLS 和证书校验。请求写入按块设 20 秒等待窗口，响应头和正文共用 30 秒窗口；到期只中断该请求独占的 socket，由原任务清理 TLS／HTTP 并保留同一任务的核对状态。中断由一个固定 2.5 KiB 静态栈的专用任务完成，不阻塞系统共用计时／事件任务；没有等待请求时休眠，不增加空闲周期唤醒。网络线程所需信号量未就绪时拒绝启动请求，中断遇到暂时资源错误则保留任务并重试。连接、DNS 和 TLS 握手仍使用 SDK 原有超时，不能将上述窗口解释为整次请求或整份录音上传的总时长上限。
