# 设备直连第三步：有卡任务

对应[主计划第三步](DEVICE_DIRECT_CLOUD_PLAN.md#步骤三-接入有卡录音流程)，基线为第二步提交 `50638e2`。遵循[第一步决定](DEVICE_DIRECT_CLOUD_STEP1.md)，只切换有卡任务；无卡和配置生产入口分别留给第四、五步。本步没有刷机、读取用户音频或凭据、调用供应商、修改服务器或发布。

## 入口与数据

- `memo_sd_sync.cpp` 执行直连任务，`network_sync.cpp` 仍由单网络工作者调度，复用 HTTP 执行门闩、对时和媒体访问互斥。新录音开始时捕获配置代次，成功保存后才创建一次持久意图；取消录音清除捕获，旧目录扫描不生成意图。仅本地录音不补传。
- `memo_direct_cache.cpp` 保存 `direct_r1_<十位编号>.job.0/.1`。每槽256字节，显式小端编码、版本、单调代次与CRC；写非当前槽、同步、关闭、回读成功后才确认。相同内容不写，损坏或未来格式不能冒充无任务。原WAV和旧 `sync_r1` 文件不改写。
- 检查点保存配置代次、文件长度、已确认样本偏移、文本字节数、阶段、尝试额度、意图和可能投递标记。每次提交对应唯一临时文本文件；没有全文RAM缓存或设备全文阅读功能。
- 必要的新配置只读接口在 `memo_cloud_config.*`：独立 `memo_cloud1/config`、604字节固定blob，含R1CF版本／模式／两项代次／Workspace／两项凭据／CRC。缺失是未配置，损坏是读取失败；不用旧token。写入、USB凭据输入和页面归第五步，此时尚无新配置生产入口。

## 分段与恢复

沿用旧后端 `iter_wav_chunks` 的适用算法：最长180秒，尾部12秒内选择绝对振幅和最低的20毫秒块作为边界。虚拟44字节WAV头加原文件区间直接流式发送，所有区间首尾相接；不生成分段音频、不计算音频SHA。读原WAV保留可失败退出的4 KiB DMA缓冲策略，空间不随录音总时长增长。

使用固定256字节工作区流式复用旧 `clean_transcript` 的CRLF、Unicode空白、边缘唤醒／停止词整理，保留正文中的控制词，不搬质量启发式；整理为空的段不落分隔符。每段只将整理后最终文本追加到卡上，段间加入空行；先同步文本，后确认样本偏移与文本长度。恢复时截去未确认尾部，短文件或I/O错误不能继续。累计文本上限256 KiB；思源正文还计入既定前缀，超限明确失败，不截断后冒称完整。完成或取消清理临时文本；失败保留唯一有界文本供阶段恢复，重新开始先清理上一次临时文本。

分段确认后不重复识别；进入投递阶段后，明确投递失败重试复用文本。每阶段请求前持久扣除额度，包括对时和等待前；同一运行期保留预留尝试，不因重复唤醒重复扣除。重启可消耗一次已经预留但尚未发出的额度，这是保守且有限的行为，不能重新得到三次。ASR最多三次、5／30秒；投递仅零HTTP字节故障或明确429共用三次、10／60秒，设备投递间隔至少10秒。Retry-After超过300秒停止，限流重启等待300秒；不在详情或目录扫描中发请求。

投递前先持久保存 `DELIVERING` 和可能发送标记；启动发现该状态或可能已投递的取消状态，转为结果不确定。明确完整成功优先于同时取消；可能已发出且响应丢失不能显示已撤回或自动重发。离线／热点开启仍可本地取消排队。媒体操作中止当前网络读取，释放门闩后按已有意图恢复。

## 历史、详情与清理

详情只读文件长度和轻量状态，不读WAV正文、不联网、不写回。无状态的合法WAV、或旧格式 `bound=false` 且状态为LOCAL／QUEUED，允许显式提交；旧服务成功、失败、上传／收据未决等保留旧来源和待核对提示，不能重新映射直连。未来格式和损坏记录关闭提交入口。同编号同长度外部替换仍是已接受的限制，不添加指纹防御。

未处理／取消／可重试失败显示提交，活动意图显示取消；已送达和结果不确定不提供普通重发。配置代次变化须显式选择当前账号；更换千问代次重新识别，更换思源代次可保留已确认文本。详情显示简短本地原因，确认弹窗沿用现有LVGL组件和三种布局。

已删除旧有卡 `remote_status`、上传分块、收据／远端查询、重试／取消RPC以及旧sidecar生产写入。`memo_sync_cache` 只保留兼容解析及尚服务于旧无卡消费者的目标比较；后者连同旧无卡请求包装归第四步。旧配置／配对调用链仍由第五步移除。后端及历史回退资料不删。对应第一步C02—C05、C17有卡部分、C23完成，其他清理归属不提前冒称完成。
